One change request per document. A recording that raises several unrelated changes produces several documents; ask the user which to write first.
Sections 3, 5, 8 and 11 hold option lists (Regulatory Requirement / Business Requirement / …, สูง / กลาง / ต่ำ / ไม่มี, Critical / High / Medium / Low, Approve / Reject). Mark the chosen option the way the template's own check mark or box works; never delete the other options.

## Not from audio
- เลขที่ CR (CR-<พ.ศ.>-nnn), Project Code — ask the user
- Request State — Initiated for a new request
- 2. ข้อมูลผู้ร้องขอ: Phone, E-mail, Other Contact — ask the user; leave empty if they skip
- 10. สถานะคำขอ — fill the Initiated row only (date, by)
- 11. การอนุมัติ — leave empty; never mark a decision

## Sections

### 1. ข้อมูลทั่วไป (General Information)
- where: table — Project Name, Request Date, Change Type, Related Document
- needs: project; date the change was asked for; type (Scope / Requirement / Design / Defect / Document); the document it changes
- required: yes
- form: fields(Project Name, Request Date, Change Type, Related Document)
- hints: "ขอเปลี่ยน", "ขอเพิ่ม", "แก้จากที่ตกลงไว้", "ตาม SRS"
- ask: การเปลี่ยนแปลงนี้กระทบเอกสารใดที่อนุมัติไปแล้ว (เช่น SRS เวอร์ชันใด)

### 2. ข้อมูลผู้ร้องขอ (Requester Contact Information)
- where: table — Requested By, Position, Department / Org.
- needs: who asked for the change, their position and organisation
- required: yes
- form: fields(Requested By, Position, Department / Org.)
- hints: "ลูกค้าขอ", "คุณ…แจ้งว่า", "ฝ่าย…ต้องการ"
- ask: ใครเป็นผู้ร้องขอการเปลี่ยนแปลงนี้ (ชื่อ-สกุล ตำแหน่ง หน่วยงาน)

### 3. วัตถุประสงค์ของการเปลี่ยนแปลง (Purpose of Change) / เหตุผลและความจำเป็น
- where: left cell — หัวข้อการเปลี่ยนแปลง, รายละเอียด, ขอบเขตงานที่เพิ่ม / เปลี่ยนแปลง, ประโยชน์ที่คาดว่าจะได้รับ; right cell — reason options and extra explanation
- needs: a short title; what is wrong or wanted and what to change; the items added or changed; the expected benefit; which reason applies
- required: yes
- form: fields(หัวข้อ, รายละเอียด, ขอบเขตงานที่เปลี่ยน, ประโยชน์) + choice(Regulatory Requirement, Business Requirement, Technical Issue, Customer Request, Defect Correction, Documentation Problem, Other)
- hints: "อยากให้เปลี่ยนเป็น", "เพราะว่า", "จะได้", "ตอนนี้ทำไม่ได้"
- ask: การเปลี่ยนแปลงนี้จำเป็นเพราะอะไร และคาดว่าจะได้ประโยชน์อะไร

### 4. ผลิตภัณฑ์ซอฟต์แวร์ / คอมโพเนนต์ที่ได้รับผลกระทบ
- where: table ลำดับ / Product / Component / Version / ประเภท / รายละเอียดผลกระทบ
- needs: which screens, modules or components change; new, modified or deleted
- required: yes
- form: table(ลำดับ, Product / Component, Version, ประเภท, รายละเอียดผลกระทบ)
- hints: "ต้องแก้หน้า", "กระทบโมดูล", "ต้องเพิ่มตาราง"
- ask: การเปลี่ยนแปลงนี้ต้องแก้หน้าจอหรือส่วนใดของระบบบ้าง

### 5. ผลกระทบต่อการทำงานของซอฟต์แวร์เดิม
- where: table of seven aspects × สูง / กลาง / ต่ำ / ไม่มี / รายละเอียด
- needs: level of impact per aspect, with a way to reduce it
- required: yes
- form: table(ด้าน, ระดับ, รายละเอียด / แนวทางลดผลกระทบ)
- hints: "จะกระทบ", "ต้องหยุดระบบ", "ข้อมูลเดิม", "ช้าลง"
- ask: การเปลี่ยนแปลงนี้กระทบการทำงานเดิมด้านใดบ้าง (ฟังก์ชัน ประสิทธิภาพ ข้อมูล การเชื่อมต่อ ความปลอดภัย ผู้ใช้ การหยุดระบบ) และระดับใด
- note: an aspect nobody discussed stays unmarked and goes into one combined question; do not mark ไม่มี by assumption.

### 6. ผลกระทบต่อเอกสารที่เกี่ยวข้อง
- where: table แก้ไข / เอกสาร / Version / รายละเอียดที่ต้องปรับปรุง
- needs: which project documents must be updated and what in them
- required: yes
- form: table(แก้ไข, เอกสาร, Version / หัวข้อ, รายละเอียดที่ต้องปรับปรุง)
- hints: "ต้องแก้เอกสาร", "ปรับ SRS", "อัปเดตแผน", "เพิ่ม test case"
- ask: ต้องปรับปรุงเอกสารใดบ้างจากการเปลี่ยนแปลงนี้ (แผน SRS Design Test case คู่มือ)

### 7. ประมาณการระยะเวลา ทรัพยากร และค่าใช้จ่าย
- where: table กิจกรรม / ระยะเวลาเพิ่ม / รายการ / ค่าใช้จ่าย
- needs: extra time per activity and extra cost
- required: yes
- form: table(กิจกรรม, ระยะเวลาเพิ่ม) + table(รายการ, ค่าใช้จ่าย)
- hints: "ใช้เวลาเพิ่ม", "เลื่อนออกไป", "ค่าใช้จ่ายเพิ่ม", "ไม่คิดเงินเพิ่ม"
- ask: ต้องใช้เวลาเพิ่มเท่าใดในแต่ละขั้น (วิเคราะห์ พัฒนา ทดสอบ) และมีค่าใช้จ่ายเพิ่มหรือไม่
- note: totals are computed only from figures that were said.

### 8. ระดับความสำคัญของคำขอ (Criticality)
- where: left cell of the 8/9 table — options and เหตุผล
- needs: Critical / High / Medium / Low and why
- required: yes
- form: choice(Critical, High, Medium, Low) + fields(เหตุผล)
- hints: "ด่วน", "ต้องมีก่อน", "ไม่รีบ", "ใช้งานไม่ได้"
- ask: คำขอนี้เร่งด่วนระดับใด และเพราะอะไร

### 9. วันที่ต้องการ (Date Needed)
- where: right cell of the 8/9 table
- needs: date wanted, the reason for that date, the effect of being late
- required: yes
- form: fields(วันที่ต้องการให้แล้วเสร็จ, เหตุผลของกำหนดเวลา, ผลกระทบหากล่าช้า)
- hints: "ต้องเสร็จก่อน", "ภายในวันที่", "ถ้าไม่ทัน"
- ask: ต้องการให้เสร็จภายในวันที่ใด และถ้าล่าช้าจะเกิดผลอะไร
