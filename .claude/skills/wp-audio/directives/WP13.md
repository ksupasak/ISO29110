## Sections

### หัวเอกสาร (header table)
- where: first table — โครงการ, รหัสโครงการ, จัดทำโดย, สถานะ
- needs: project or system name
- required: yes
- form: fields(โครงการ)
- hints: "โครงการ", "ระบบ"
- ask: ชื่อโครงการหรือชื่อระบบอย่างเป็นทางการคืออะไร

### 1. บทนำ (Introduction)
- where: lines วัตถุประสงค์, ขอบเขต, เอกสารอ้างอิง
- needs: what the system is for; what is in and out of scope; documents referred to (agreement, meeting records)
- required: yes
- form: fields(วัตถุประสงค์, ขอบเขต, เอกสารอ้างอิง)
- hints: "ต้องการระบบเพื่อ", "ปัญหาตอนนี้คือ", "ไม่รวม", "ยังไม่ต้องทำ"
- ask: ระบบนี้มีไว้เพื่อแก้ปัญหาอะไร และมีอะไรที่อยู่นอกขอบเขตงานรอบนี้

### 2.1 กลุ่มผู้ใช้ (User Classes)
- where: table บทบาท / การใช้งาน / จำนวนโดยประมาณ
- needs: each kind of user, what they do with the system, roughly how many
- required: yes
- form: table(บทบาท, การใช้งาน, จำนวนโดยประมาณ)
- hints: "ผู้ใช้มี", "แอดมิน", "พนักงาน", "ลูกค้าจะเข้ามา", "ประมาณกี่คน"
- ask: ใครเป็นผู้ใช้ระบบบ้าง แต่ละกลุ่มใช้ทำอะไร และมีประมาณกี่คน

### 2.2 สภาพแวดล้อมการใช้งาน ข้อจำกัด และสมมติฐาน
- where: bullet list under 2.2
- needs: where it runs (browser, mobile, server), constraints, assumptions
- required: no
- form: bullets
- hints: "ใช้ผ่าน", "ติดตั้งบน", "ต้องใช้กับ", "สมมติว่า", "ข้อจำกัด"
- ask: ระบบจะใช้งานผ่านอะไร (เว็บ มือถือ) ติดตั้งที่ไหน และมีข้อจำกัดอะไรที่ต้องรู้

### 3. ความต้องการด้านฟังก์ชัน (Functional Requirements)
- where: table ID / ความต้องการ / Priority / ที่มา / เกณฑ์การยอมรับ
- needs: one row per thing the system must do, written as "ผู้ใช้/ระบบ … ได้"; priority; source; how to tell it is done
- required: yes
- form: table(ID, ความต้องการ, Priority, ที่มา, เกณฑ์การยอมรับ)
- hints: "ระบบต้อง", "อยากให้", "ผู้ใช้ต้อง…ได้", "ขอเพิ่ม", "ต้องมี"
- ask: ความต้องการ «…» สำคัญระดับใด (High / Medium / Low) และจะถือว่าผ่านเมื่อระบบทำอะไรได้
- note: one requirement per row; split "และ". ที่มา = the recording (file name + timestamp) unless an agreement item is named. Priority and acceptance criterion are written only when said; otherwise they are questions, one per requirement, and the cell holds the waiting marker.

### 4. ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-functional Requirements)
- where: table ID / ประเภท / ความต้องการ / ที่มา
- needs: speed, capacity, security, availability, usability, with the number that was said
- required: yes
- form: table(ID, ประเภท, ความต้องการ, ที่มา)
- hints: "ภายใน…วินาที", "รองรับ…คน", "ปลอดภัย", "สำรองข้อมูล", "ใช้งานได้ตลอด"
- ask: มีข้อกำหนดด้านความเร็ว จำนวนผู้ใช้พร้อมกัน ความปลอดภัย หรือการสำรองข้อมูลหรือไม่
- note: a requirement without a measurable number is recorded as said and its number becomes a question.

### 5. ความต้องการด้าน Interface
- where: table Interface / รายละเอียด
- needs: user interface language and devices; connections to other systems (email, SSO, other databases)
- required: no
- form: table(Interface, รายละเอียด)
- hints: "เชื่อมกับ", "ส่งอีเมล", "ดึงข้อมูลจาก", "ภาษาไทย", "ใช้บนมือถือ"
- ask: ระบบต้องเชื่อมต่อกับระบบอื่นหรือบริการภายนอกใดบ้าง

### 6. ข้อมูลหลักของระบบ (Data Requirements)
- where: table Entity / ข้อมูลสำคัญ
- needs: the main things the system stores and their key fields
- required: no
- form: table(Entity, ข้อมูลสำคัญ)
- hints: "เก็บข้อมูล", "ต้องบันทึก", "ข้อมูล…ประกอบด้วย"
- ask: ระบบต้องเก็บข้อมูลหลักอะไรบ้าง และแต่ละอย่างมีรายละเอียดอะไรที่จำเป็น
