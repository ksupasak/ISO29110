The template contains a worked sample (an internal TaskDoc project): bracketed text, and also unbracketed sample rows in sections 2–5, 7 and 8. Treat every project-specific statement in it as sample form. Fixed wording that is not project-specific (role descriptions in section 1, the note under it) stays.

## Not from audio
- รหัสโครงการ, วันที่ทำข้อตกลง, สถานะเอกสาร — ask the user (status of a new document: none ticked)
- ประเภทโครงการ (ภายใน / ลูกค้าภายนอก) — ask the user if not evident
- 9. การลงนาม — leave as in template

## Sections

### หัวเอกสาร (header table)
- where: first table — ชื่อโครงการ, ระยะเวลาโครงการ
- needs: project name; start and end date or length
- required: yes
- form: fields(ชื่อโครงการ, ระยะเวลาโครงการ)
- hints: "โครงการ", "เริ่ม", "ให้เสร็จภายใน", "ใช้เวลา…เดือน"
- ask: โครงการนี้ชื่ออะไร เริ่มและสิ้นสุดเมื่อใด

### 1. คู่สัญญา (Parties)
- where: table ฝ่าย / ผู้แทน / บทบาท — fill the ผู้แทน column only
- needs: name and position of the customer (project owner), the user representative, the project manager, the approving executive
- required: yes
- form: table(ฝ่าย, ผู้แทน)
- hints: "เจ้าของโครงการ", "ผู้ประสานงาน", "ผู้จัดการโครงการ", "ผู้อนุมัติ"
- ask: ใครเป็นเจ้าของโครงการ ผู้แทนผู้ใช้งาน ผู้จัดการโครงการ และผู้บริหารที่อนุมัติ (ชื่อ-สกุลและตำแหน่ง)

### 2. ความเป็นมาและรายละเอียดผลิตภัณฑ์ (Product Description)
- where: paragraphs under heading 2
- needs: the current situation and problem; what will be built, in two short paragraphs
- required: yes
- form: paragraph
- hints: "ตอนนี้ทำงานกันแบบ", "ปัญหาคือ", "อยากได้ระบบที่"
- ask: ปัจจุบันทำงานนี้กันอย่างไร มีปัญหาอะไร และระบบที่จะพัฒนาคืออะไรโดยสรุป

### 3. ขอบเขตงาน (Scope Description)
- where: two-column table รวมอยู่ในขอบเขต / ไม่รวมอยู่ในขอบเขต
- needs: what is included; what is explicitly excluded
- required: yes
- form: table(รวมอยู่ในขอบเขต, ไม่รวมอยู่ในขอบเขต)
- hints: "รวมถึง", "ไม่รวม", "ยังไม่ทำ", "เฟสหน้า", "ลูกค้าจัดหาเอง"
- ask: มีอะไรที่ตกลงกันว่าไม่รวมอยู่ในงานนี้

### 4. วัตถุประสงค์ของโครงการ (Objectives)
- where: table ลำดับ / วัตถุประสงค์ / ตัวชี้วัดความสำเร็จ
- needs: each objective with a measure of success
- required: yes
- form: table(ลำดับ, วัตถุประสงค์, ตัวชี้วัดความสำเร็จ)
- hints: "เป้าหมายคือ", "อยากให้ลด", "วัดจาก"
- ask: วัตถุประสงค์ «…» จะวัดความสำเร็จจากอะไร

### 5. สิ่งส่งมอบ (Deliverables)
- where: table ลำดับ / รายการ / รูปแบบ / กำหนดส่ง
- needs: what will be handed over (software, documents, training) and when
- required: yes
- form: table(ลำดับ, รายการ, รูปแบบ, กำหนดส่ง)
- hints: "ส่งมอบ", "ต้องมีคู่มือ", "อบรม", "ส่งงวดแรก"
- ask: สิ่งที่ต้องส่งมอบมีอะไรบ้าง และแต่ละรายการกำหนดส่งเมื่อใด
- note: the template lists the standard ISO 29110 work products; keep those rows the user confirms and fill only dates that were said.

### 6. ระยะเวลา ทรัพยากร และงบประมาณ
- where: table — ระยะเวลา, ทีมงาน, แรงงานโดยประมาณ, งบประมาณ, การศึกษาความเป็นไปได้, Development cycle
- needs: duration, team make-up, effort, budget, delivery rounds
- required: yes
- form: fields(ระยะเวลา, ทีมงาน, แรงงานโดยประมาณ, งบประมาณ, Development cycle)
- hints: "งบ", "กี่คน", "man-day", "ส่งเป็นงวด", "กี่รอบ"
- ask: งบประมาณ ขนาดทีม และจำนวนรอบการส่งมอบที่ตกลงกันคือเท่าใด

### 7. ความรับผิดชอบและเงื่อนไขร่วมกัน
- where: bullet list under heading 7
- needs: what each side commits to (customer gives information and time, team reports progress, how changes are handled)
- required: yes
- form: bullets
- hints: "ลูกค้าจะ", "ทางเราจะ", "ถ้ามีการเปลี่ยนแปลง", "รายงานทุก"
- ask: แต่ละฝ่ายรับผิดชอบอะไร และถ้ามีการขอเปลี่ยนแปลงจะจัดการอย่างไร

### 8. เกณฑ์การตรวจรับ (Acceptance Criteria)
- where: bullet list under heading 8
- needs: the conditions under which the customer accepts the product
- required: yes
- form: bullets
- hints: "ตรวจรับ", "ถือว่าผ่านเมื่อ", "UAT", "ต้องไม่มีบั๊ก"
- ask: ลูกค้าจะตรวจรับงานด้วยเกณฑ์อะไร
