# เปลี่ยนหน้าตาระบบเป็น Admin Theme แบบ Material Design บน Bootstrap 5 — เอกสารออกแบบ (ฉบับสั้น)

วันที่: 23/11/2569 · สถานะ: รออนุมัติ · ต่อจาก Release 1 (branch main)

## เจตนา

ผู้ใช้ต้องการให้ระบบดูเป็น admin dashboard ที่สวยงามในสไตล์ Material Design และสร้างบน Bootstrap เพื่อให้ทีมที่คุ้น Bootstrap ดูแลต่อได้ ทำตอนนี้เพราะระบบยังมีเพียงรุ่น 1 (6 กลุ่มหน้าจอ) รุ่น 2–6 จะสร้างบนชุด UI ใหม่ตั้งแต่ต้น

## เป้าหมาย / ไม่ทำ / ห้ามเกิด

- **เป้าหมาย:** ทุกหน้าจอของรุ่น 1 ใช้ Bootstrap 5 + ธีม Material; โครงหน้าแบบ admin (เมนูด้านข้าง + แถบบน); ฟอนต์ไทยอ่านง่าย; ใช้ได้บนจอมือถือ
- **ไม่ทำ:** ไม่เปลี่ยนกฎการทำงาน สิทธิ์ ฐานข้อมูล หรือข้อความภาษาไทยที่มีอยู่; ไม่เพิ่มฟีเจอร์ใหม่นอกจากการ์ดสรุปบนหน้ารวม; ไม่ทำ dark mode
- **ห้ามเกิด:** เหลือ Tailwind/shadcn ปนกับ Bootstrap; test เดิมพัง; ต้องพึ่ง CDN ภายนอกตอนใช้งาน (server อาจอยู่ในเครือข่ายภายใน)

## แนวทางที่พิจารณา

| แนวทาง | ผล |
|---|---|
| **A. Bootstrap 5 + ธีม Material จริง แทน Tailwind/shadcn** | **ผู้ใช้เลือก** ตรงตามที่ขอ ดูแลต่อง่าย งานมากสุดแต่ทำครั้งเดียว |
| B. คง Tailwind แล้วแต่งให้เหมือน Material | งานน้อยกว่า แต่ไม่ใช่ Bootstrap |
| C. ใส่ Bootstrap เพิ่มทับของเดิม | CSS ตีกัน หน้าเว็บหนัก |

## การออกแบบ

### เครื่องมือ (ผู้ออกแบบเลือก)

- `bootstrap@5.3` (Sass) + `react-bootstrap` สำหรับ Modal, Dropdown, Offcanvas, Toast, Form — รองรับ React 19 และไม่ต้องใช้ JavaScript ของ Bootstrap เอง
- ธีม Material เขียนเป็น Sass ของโปรเจกต์เองใน `src/styles/` โดยปรับตัวแปรของ Bootstrap: สี เงาแบบ elevation มุมโค้ง ปุ่ม ช่องกรอกแบบ floating label การ์ดที่หัวมีแถบสี
- ไม่ใช้ธีมสำเร็จรูป (Material Dashboard, MDB): ทั้งสองผูกกับ JavaScript ของตัวเองซึ่งไม่เข้ากับ React server components และทำให้อัปเกรดยาก ผลที่ตามองเห็นเทียบเท่ากัน
- ไอคอน: Material Symbols (Outlined) ติดตั้งผ่าน npm และเสิร์ฟจาก server เอง
- ฟอนต์: Sarabun (ไทย + ละติน) ผ่าน `next/font` ซึ่งฝังไฟล์ฟอนต์ตอน build ไม่เรียก CDN ตอนใช้งาน
- ถอด: `tailwindcss`, shadcn components (`src/components/ui`), `cn`, `src/lib/utils.ts`, การตั้งค่าที่เกี่ยวข้อง

### สี

| บทบาท | ค่า | ใช้กับ |
|---|---|---|
| Primary | `#1F3864` (กรมท่า ชุดเดียวกับหัวเอกสาร ISO ที่ส่งออก) | เมนูด้านข้าง ปุ่มหลัก หัวการ์ด |
| Secondary | `#00897B` (Material Teal 600) | ปุ่มรอง ลิงก์เน้น |
| Success / Warning / Danger / Info | `#43A047` / `#FB8C00` / `#E53935` / `#1E88E5` | badge สถานะ ข้อความแจ้ง |
| พื้นหลัง | `#F4F6F9` | พื้นหน้า; การ์ดสีขาวมีเงา |

สี badge สถานะเอกสาร: Draft เทา; สถานะระหว่างทาง (Reviewed, Verified, Initiated ฯลฯ) ฟ้า; สถานะสุดท้าย (Approved, Baselined, Accepted, Signed, Published, Completed) เขียว; Rejected แดง
สี badge สถานะโครงการ: วางแผน ฟ้า; ดำเนินการ เขียว; ปิดโครงการ เทา

### หน้าจอ

| หน้า | สิ่งที่เปลี่ยน |
|---|---|
| Login | การ์ด Material กลางจอ ช่องกรอก floating label |
| หน้ารวม `/` | แถวการ์ดสรุป 3 ใบ: จำนวนโครงการที่เห็น, กำลังดำเนินการ, ปิดแล้ว (นับจากรายการเดิม ไม่มี query ใหม่นอกจากการนับ) แล้วตามด้วยการ์ดโครงการแบบ grid |
| ผู้ใช้งาน | ตารางในการ์ด ปุ่มไอคอนต่อแถว Modal สำหรับสร้าง/แก้ไข/ตั้งรหัสผ่าน |
| ภาพรวมโครงการ | การ์ดข้อมูลโครงการ (2 คอลัมน์) + การ์ดทีม (ตาราง, badge บทบาท) |
| คลังเอกสาร | Accordion 9 ช่วงงาน; แต่ละ WP เป็นแถวที่ขยายได้ แสดงเวอร์ชัน/หลักฐาน; badge สถานะตามสีข้างบน |
| 404 / error | การ์ดกลางจอ ข้อความเดิม |
| Dialog ทั้งหมด | `FormDialog` ตัวเดียวบน react-bootstrap Modal; dialog ของหน้าผู้ใช้งานย้ายมาใช้ตัวเดียวกัน (ปิดรายการค้าง "FormDialog ซ้ำซ้อน") |

### สิ่งที่ต้องคงไว้

- ข้อความ ป้ายกำกับ และข้อความแจ้งข้อผิดพลาดภาษาไทยเหมือนเดิมทุกตัวอักษร (test e2e อ้างอิง)
- `data-testid="phase-heading"` และ `data-testid="wp-row"`
- services, actions, authz, storage, schema ไม่แก้
- การตรวจขนาดไฟล์ 50 MB ฝั่ง client และการซ่อนปุ่มตามสิทธิ์

### การทดสอบ

- `npm test` (142 ข้อ), `npm run lint`, `npm run build` ผ่าน
- `npm run test:e2e` ผ่าน โดยแก้ selector เฉพาะที่โครง DOM เปลี่ยน ไม่ลดสิ่งที่ตรวจ; เพิ่ม 1 ขั้น: ย่อจอเป็น 390px แล้วเปิดเมนูด้วยปุ่ม ☰ และไปหน้าเอกสารได้
- ตรวจด้วยตา: ภาพหน้าจอทุกหน้าที่ความกว้าง 1440px และ 390px แนบในรายงาน
- ตรวจว่าไม่มีคำขอไปยังโดเมนภายนอกตอนเปิดหน้า (ฟอนต์ ไอคอน CSS)
