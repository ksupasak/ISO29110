# รุ่น 2: แผนงาน สายการอ้างอิง Meeting Record และคลัง template — เอกสารออกแบบ

วันที่: 24/11/2569 · สถานะ: อนุมัติ 24/11/2569 · ต่อจาก main `3efd061`
เอกสารแม่: `2026-11-23-project-management-system-design.md` (ข้อ 6.2 สิทธิ์, 6.3 โมเดลข้อมูล, 6.4 กฎ, 8 สายการอ้างอิง) เอกสารนี้ระบุเฉพาะสิ่งที่รุ่น 2 สร้างและสิ่งที่เปลี่ยนจากเอกสารแม่

## 1. เจตนา

ผู้ใช้ต้องการให้เอกสารที่เกิดซ้ำหลายครั้งและอ้างอิงกัน (เริ่มที่ Meeting Record) กรอกผ่าน web form ครบทุกช่อง ออกรหัสอัตโนมัติ และไล่ตามรอยได้ตั้งแต่ Requirement → Dev task → Component เพื่อเลิกพิมพ์รหัสอ้างอิงด้วยมือในไฟล์ Word และเพื่อให้ผู้ประเมิน ISO/IEC 29110 เห็นความเชื่อมโยง

ผู้ใช้ต้องการให้ทีมดาวน์โหลด template และตัวอย่างของแต่ละ WP จากระบบได้ และให้ admin แก้ template ที่โฟลเดอร์บน server ได้เอง โดยเอกสารที่ระบบส่งออกเปลี่ยนตาม template ที่แก้

### คำที่ใช้ในเอกสารนี้

- **เอกสารที่กรอกผ่าน web form** (เดิมเขียนว่า "เอกสารที่ระบบสร้าง"): ผู้ใช้กรอกข้อมูลในฟอร์มบนเว็บ ระบบเก็บลงฐานข้อมูล แล้วเติมข้อมูลลงไฟล์ template ออกมาเป็น docx ผู้ใช้ไม่ต้องเปิด Word พิมพ์ ได้แก่ WP03 Change Request, WP04 Correction Register, WP07 Meeting Record, WP09 Progress Status Record, WP11 ทะเบียน Project Repository, WP12 Backup Log, WP19 Test Cases, WP20 Test Report, WP21 Traceability Record, WP22 Validation Record, WP23 Verification Record (รุ่น 2 ทำ WP07; ที่เหลือตามลำดับรุ่น)
- **เอกสารที่เขียนใน Word แล้วแนบ**: WP ที่เหลือ 12 รายการ (เช่น Agreement, Project Plan, SRS, Software Design, คู่มือ) ผู้ใช้ดาวน์โหลด template ไปเขียน แล้วอัปโหลดเป็นเวอร์ชันในคลังเอกสาร

## 2. เป้าหมาย / ไม่ทำ / ห้ามเกิด

**เป้าหมาย**
- Milestone และ WBS/Task ต่อโครงการ มีรหัส `T-nnn`
- ขอบเขตตาม Agreement (`AG-nn`), Requirement (`REQ-Fnn` / `REQ-Nnn`), Component (`Cnn`) และการโยง AG → REQ → Task → Component
- Meeting Record ฟอร์มครบ 9 หัวข้อของ template WP07 ออกเลขที่ `MR-<พ.ศ.>-nn` ส่งออก docx
- ทุก WP ดาวน์โหลด template และไฟล์ตัวอย่างได้จากหน้าคลังเอกสาร
- เอกสารที่ระบบส่งออกสร้างจากไฟล์ template ในโฟลเดอร์บน server
- ผู้ใช้เปลี่ยนรหัสผ่านของตนเอง

**ไม่ทำในรุ่นนี้**
- Change Request, Correction, Progress Status, risk, budget (รุ่น 3)
- Test Case, Defect, Traceability Record ที่ส่งออกเป็น WP21 (รุ่น 5)
- หน้าอัปโหลด/แก้ template ผ่านเว็บ; admin แก้ไฟล์ที่ server
- มุมมองกระดาน (kanban) ของ Task และ Gantt
- การปลดล็อกพร้อมเหตุผลและ audit log (รุ่น 6)

**ห้ามเกิด**
- รหัสซ้ำกันหรือถูกนำกลับมาใช้ใหม่หลังลบ
- เอกสารส่งออกมีหัวข้อหรือหัวตารางต่างจาก template ในโฟลเดอร์
- template ที่ admin แก้ผิดทำให้ระบบล่ม (ต้องแจ้งข้อผิดพลาดเป็นข้อความที่บอกว่าผิดตรงไหน)
- ดาวน์โหลดไฟล์นอกโฟลเดอร์ template ได้ (path traversal)

## 3. สิ่งที่ผู้ใช้ตัดสินใจ

- ประเด็นค้างจากการประชุมกลายเป็น Task เมื่อผู้บันทึกกดปุ่ม "สร้าง Task" ไม่สร้างอัตโนมัติ
- การแก้ template ต้องมีผลกับเอกสารที่ระบบส่งออก (เติมข้อมูลลง template แทนหน้าตาที่ฝังในโค้ด)
- admin จัดการโฟลเดอร์ template ที่ server โดยตรง

## 4. แนวทางที่พิจารณา

**การแบ่งงาน** — ผู้ออกแบบเลือก A (ผู้ใช้ไม่คัดค้าน)

## 5. การออกแบบ

### 5.1 คลัง template (2A)

- สองโฟลเดอร์: `templates-default/` (มากับระบบ อยู่ใน git, `TEMPLATES_DEFAULT_DIR`; เนื้อหาตั้งต้นคัดลอกจาก `../repository/FRA_flora_01` — 9 โฟลเดอร์ช่วงงาน / 23 โฟลเดอร์ WP, template 23 ไฟล์, ตัวอย่าง 31 ไฟล์ — ห้ามแก้บน server) และ `templates/` (override ของ admin, `TEMPLATES_DIR` ค่าเริ่มต้น `./templates`, ไม่อยู่ใน git; ใน Docker ผูกโฟลเดอร์ของเครื่อง server `./templates:/data/templates` แบบอ่านอย่างเดียว ไม่ใช้ named volume)
- เลือกไฟล์ราย WP: ถ้า `templates/` มี template ของ WP ใด ใช้ไฟล์นั้น ไม่เช่นนั้นใช้ของ `templates-default/`; ตัวอย่างรวมจากทั้งสองโฟลเดอร์ ชื่อซ้ำใช้ของ `templates/`
- การจับคู่ อ่านสดทุกคำขอ ไม่เก็บ cache ข้ามคำขอ:
  - โฟลเดอร์ระดับใดก็ได้ที่ชื่อมี `WPnn` (สองหลัก) เป็นของ WP นั้น
  - ไฟล์ในโฟลเดอร์นั้นที่ชื่อขึ้นต้น `WPnn_` คือ template (ถ้ามีหลายไฟล์ ใช้ไฟล์แรกตามลำดับชื่อ และหน้าตรวจ template เตือน)
  - ไฟล์อื่นในโฟลเดอร์เดียวกันคือตัวอย่าง; ข้ามไฟล์ซ่อนและไฟล์ชั่วคราวของ Word (`~$…`)
- หน้าคลังเอกสาร: ในแถวที่ขยายของแต่ละ WP มีปุ่ม `ดาวน์โหลด template` และรายการ `ตัวอย่าง (n)`; ถ้าไม่มีไฟล์ ไม่แสดงปุ่ม
- การดาวน์โหลด: ผู้ใช้ที่ login แล้วทุกคน; ระบุด้วยรหัส WP และชื่อไฟล์ ซึ่งต้องตรงกับรายการที่สแกนได้เท่านั้น
- WP ที่ระบบสร้างเอง (รุ่นนี้คือ WP07) มีไฟล์ template เดียวที่มีเครื่องหมาย; ปุ่ม `ดาวน์โหลด template` ของ WP นั้นส่งไฟล์ที่เติมค่าว่างแล้ว (ตารางรายการมีแถวเปล่า 3 แถว) เพื่อให้คนกรอกมือได้โดยไม่เห็นเครื่องหมาย
- หน้า `/admin/templates` (ADMIN): ตาราง 23 WP แสดงไฟล์ template ที่พบ จำนวนตัวอย่าง และผลตรวจของ WP ที่ระบบสร้าง (เครื่องหมายที่ต้องมีครบหรือไม่, ลองเติมข้อมูลตัวอย่างแล้วผ่านหรือไม่, ข้อความผิดพลาด) พร้อมตารางอ้างอิงชื่อเครื่องหมายของแต่ละ WP

### 5.2 ตัวเติม template (2B)

- ไลบรารี `docxtemplater` + `pizzip` (ผู้ออกแบบเลือก; รองรับการวนแถวตารางและเครื่องหมายที่ Word ตัดข้าม run)
- ชื่อเครื่องหมายเป็นอักษรอังกฤษ เช่น `{projectName}`; รายการซ้ำใช้ `{#attendees}…{/attendees}`; ช่องติ๊กสถานะใช้เครื่องหมายที่ให้ค่า ☐ หรือ ☑
- แต่ละ WP ที่ระบบสร้างมีโมดูลหนึ่งตัวที่ประกาศ: รายการเครื่องหมายที่ต้องมี, ฟังก์ชันแปลงข้อมูลจากฐานข้อมูลเป็นค่าที่เติม, ข้อมูลตัวอย่างสำหรับการตรวจ
- ค่าว่างเติมเป็นข้อความว่าง ไม่พิมพ์ `undefined`; วันที่เป็น วว/ดด/ปปปป พ.ศ.
- ถ้าไม่พบไฟล์ template หรือเติมไม่ผ่าน: การส่งออกตอบข้อความไทยที่ระบุ WP และสาเหตุ ไม่ส่งไฟล์เสีย

### 5.3 ตัวออกรหัส (2A)

- ตาราง `doc_sequence` (project, prefix, ปี พ.ศ. หรือว่าง, last_no) เพิ่มค่าใน transaction เดียวกับการสร้างรายการ สองคำขอพร้อมกันต้องได้เลขต่างกัน
- รูปแบบตามเอกสารแม่ข้อ 6.4(3): `MR-2569-01` (นับใหม่ทุกปี พ.ศ. ตามวันที่ประชุม), `T-001`, `AG-01`, `REQ-F01`, `REQ-N01`, `C01`, `M1`
- รหัสออกครั้งเดียว แก้ไม่ได้ ลบรายการแล้วไม่นำเลขกลับมาใช้

### 5.4 ข้อมูล

ตามเอกสารแม่ข้อ 6.3 และ 8.1 สำหรับ: `milestone`, `task`, `agreement_item`, `requirement`, `component`, `requirement_component`, `task_requirement`, `task_component`, `meeting`, `meeting_attendee`, `meeting_item` ข้อกำหนดเพิ่ม:

- `task`: มี `code` (`T-nnn`), `kind` (Plan/Dev/Fix/Review), `wbs_code` (ผู้ใช้กรอก เช่น 2.1.3), `parent`, `milestone` (ไม่บังคับ) ช่องอื่นตามเอกสารแม่; `defect_id` เพิ่มในรุ่น 5
- `requirement.added_by_cr` เพิ่มในรุ่น 3
- `meeting_attendee`: ชื่อ-สกุล, ตำแหน่ง, หน่วยงาน, บทบาทในโครงการ, เข้าร่วม/ไม่เข้าร่วม; เลือกจากสมาชิกโครงการ (เติมชื่อ ตำแหน่ง บทบาทให้) หรือพิมพ์ชื่อบุคคลภายนอก
- `meeting_item`: kind (Accomplished / Issue / OpenIssue / Agreement), ลำดับ, ข้อความ; เฉพาะ OpenIssue มี ผู้รับผิดชอบ, กำหนดชี้แจง, สถานะ (ค้าง/ปิดแล้ว), `linked_type`+`linked_id` (รุ่นนี้โยงได้เฉพาะ task), และ `carried_from` (ประเด็นต้นทางในการประชุมครั้งก่อน)
- `meeting`: ช่องตาม template — หัวข้อ, วันที่, เวลาเริ่ม–สิ้นสุด, สถานที่, ผู้บันทึก, ผู้จัดประชุม, วัตถุประสงค์, อ้างอิงการประชุมครั้งก่อน (เลือกจากรายการ หรือ "ไม่มี"), การประชุมครั้งต่อไป (หัวข้อ, วันที่, เวลา, สถานที่), สถานะ Draft/Approved
- ลบรายการที่ถูกโยงอยู่ไม่ได้ ระบบแจ้งว่าถูกอ้างจากรายการใด

### 5.5 กฎ

1. **สร้าง Task จากประเด็นค้าง:** ปุ่มในแถวประเด็นค้างเปิดฟอร์ม Task ที่เติมชื่องาน ผู้รับผิดชอบ และวันสิ้นสุดตามแผนจากประเด็น บันทึกแล้วโยงกลับที่ประเด็น; เลือกโยงกับ Task ที่มีอยู่ได้เช่นกัน ประเด็นที่โยงกับ Task แสดงสถานะตาม Task (Done = ปิดแล้ว) และแก้สถานะเองไม่ได้
2. **ยกประเด็นค้างมา:** เมื่อสร้างการประชุมและเลือกการประชุมครั้งก่อน ระบบคัดลอกประเด็นค้างที่ยังไม่ปิดมาเป็นประเด็นค้างของครั้งใหม่ พร้อม `carried_from`; ผู้บันทึกลบหรือแก้ได้
3. **Approved:** Meeting ที่ Approved แก้ไม่ได้ PM เปลี่ยนกลับเป็น Draft ได้ (เหตุผลและ audit log มาในรุ่น 6)
4. **สิทธิ์** ตามเอกสารแม่ข้อ 6.2: Milestone และ Task — PM; ผู้รับผิดชอบแก้สถานะ, %, วันจริง, จำนวนวันที่ใช้ของ Task ตนเอง; AG, Requirement, Component และการโยง — AN, TL; Meeting — PM, AN สร้าง/แก้, PM อนุมัติ; สมาชิกทุกคนอ่านได้
5. **Requirement:** รายการในระบบเป็นแหล่งออกรหัส ไฟล์ SRS ที่แนบอ้างรหัสเดียวกัน (ผู้ออกแบบเสนอ ผู้ใช้ไม่คัดค้าน)
6. **ไฟล์แนบของ Meeting:** ใช้ `Attachment` เดิม (entity `meeting`) เพื่อแนบฉบับที่ลูกค้าเซ็น ชนิด Signed
7. **เปลี่ยนรหัสผ่าน:** ต้องกรอกรหัสเดิม รหัสใหม่ใช้กฎความยาวเดียวกับที่ admin ตั้ง; สำเร็จแล้ว session อื่นของผู้ใช้นั้นถูกยกเลิก

### 5.7 การทดสอบ

- Unit (ฐานข้อมูลจริง): ตัวออกรหัสเมื่อเรียกพร้อมกัน; สิทธิ์แต่ละบทบาทต่อแต่ละการกระทำ; การลบรายการที่ถูกโยง; การยกประเด็นค้าง; สถานะประเด็นตาม Task; การสแกนโฟลเดอร์ template (ชื่อผิดรูป, ไฟล์ `~$`, path traversal)
- ส่งออก: เติม WP07 ด้วยข้อมูลการประชุมตัวอย่าง แล้วตรวจว่าหัวข้อ 9 ข้อและหัวตารางของ template ปรากฏครบ ค่าที่กรอกปรากฏ ไม่มีเครื่องหมายเหลือ; template ที่ลบเครื่องหมายออกหนึ่งตัวต้องได้ข้อความผิดพลาดที่ระบุชื่อเครื่องหมาย
- E2E: 2A — สร้าง AG → Requirement → Task → Component โยงกัน แล้วเห็นในหน้า trace และดาวน์โหลด template ของ WP หนึ่งได้; 2B — สร้างการประชุม เพิ่มประเด็นค้าง กดสร้าง Task อนุมัติ ส่งออก docx แล้วสร้างการประชุมครั้งถัดไปที่ยกประเด็นค้างมา

### 5.8 ข้อชี้ขาดหลังการตรวจในมุมผู้สร้าง (ผู้ออกแบบตัดสิน เว้นแต่ระบุว่าผู้ใช้)

**Meeting Record**
1. **ฉบับอนุมัติไม่เปลี่ยน:** เมื่อกด Approved ระบบสร้าง docx และเก็บเป็นไฟล์แนบของการประชุมนั้น (ฉบับอนุมัติ) การส่งออกหลังจากนั้นส่งไฟล์ที่เก็บไว้ ไม่สร้างใหม่ จึงไม่เปลี่ยนตามสถานะ Task หรือ template ที่แก้ภายหลัง เมื่อ PM เปลี่ยนกลับเป็น Draft แล้วอนุมัติใหม่ ระบบสร้างฉบับใหม่แทน
2. **ผู้กดสร้าง Task จากประเด็นค้าง:** ผู้ที่แก้การประชุมนั้นได้ (PM, AN) สร้าง Task ผ่านปุ่มนี้ได้ แม้ AN จะสร้าง Task จากหน้าแผนงานไม่ได้ Task ที่ได้เป็นชนิด Plan และ PM แก้ต่อได้
3. **เลขที่:** `MR-<พ.ศ.>-nn` สองหลัก ตามเอกสารแม่และไฟล์ตัวอย่าง (ข้อความ `MR-YYYY-NNN` ในหัวกระดาษ template เป็นเพียงตัวอย่างรูปแบบ) ปี พ.ศ. มาจากวันที่ประชุมตามเวลา Asia/Bangkok ออกเลขตอนสร้าง แก้วันที่ภายหลังเลขไม่เปลี่ยน หัวกระดาษ: Version `1.0`, Date = วันที่ประชุม
4. **โลโก้และชื่อบริษัท:** อยู่ในไฟล์ template โดยตรง admin เปลี่ยนโดยแก้ template ระบบไม่เติมรูป (แทนเอกสารแม่ข้อ 6.6 บรรทัดสุดท้าย)
5. **ผู้เข้าร่วม:** ตารางแสดงเฉพาะผู้เข้าร่วม ผู้ไม่เข้าร่วมพิมพ์ในบรรทัด "ผู้ไม่ได้เข้าร่วม" คั่นด้วยจุลภาค ว่างได้; "บทบาทในโครงการ" ของสมาชิกเติมจากบทบาทหลัก แก้ได้; "หน่วยงาน" เป็นข้อความที่ผู้บันทึกกรอก; ช่องลงชื่อเว้นว่างเหมือน template
6. **การยกประเด็นค้าง:** คัดลอกครั้งเดียวตอนสร้าง การแก้การประชุมครั้งก่อนภายหลังไม่มีผล; การประชุมครั้งก่อนไม่ต้อง Approved; Task ที่ไม่ใช่ Done ถือว่า "ค้าง"
7. **การลบ:** ลบได้เฉพาะ Meeting ที่เป็น Draft และไม่มีประเด็นที่ถูกยกไปครั้งถัดไป; Task ที่สร้างจากประเด็นยังอยู่ เลขที่ไม่นำกลับมาใช้

**สถานะ**
- Task: Todo / Doing / Done / Blocked
- Requirement: Proposed / Approved / Dropped; TL (หรือ PM) เปลี่ยนเป็น Approved; Requirement ที่ Approved แก้ข้อความไม่ได้จนกว่าจะเปลี่ยนสถานะกลับ
- Component: ไม่มีสถานะรายการ มี `unit_test_status` (ยังไม่ทดสอบ / ผ่าน / ไม่ผ่าน)

**template และตัวเติม**
- template WP07 ที่มีเครื่องหมายต้องต่างจากไฟล์ปัจจุบันสามจุด: ช่องติ๊ก Draft/Approved เปลี่ยนจาก content control เป็นข้อความธรรมดาที่เป็นเครื่องหมาย; เครื่องหมายใช้รูปแบบตัวอักษรปกติ ไม่ใช่สีเทาตัวเอียงของข้อความตัวอย่างเดิม; แถวข้อมูลของตารางซ้อนเหลือแถวเดียวที่วนซ้ำ
- การตรวจ "เครื่องหมายครบ" ทำโดยอ่านรายชื่อเครื่องหมายจากไฟล์เทียบกับรายการที่โมดูลประกาศ
- `doc_sequence` ที่ไม่มีปีเก็บปีเป็น 0 เพื่อให้ unique index ใช้ได้
- README ต้องอธิบายตำแหน่งโฟลเดอร์ template สิทธิ์อ่านไฟล์ของผู้ใช้ใน container (uid 1001) และวิธีแก้ template แล้วกดตรวจ
- ไฟล์ template ของ WP07 ใน `FRA_flora_01` และ `project_templates` มีเนื้อหาเดียวกัน จึงใช้ `FRA_flora_01` เป็นเนื้อหาตั้งต้นได้
